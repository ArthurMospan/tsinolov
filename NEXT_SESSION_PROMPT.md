# Промпт для наступної сесії: Створення Smart Watchlist Bot (Сільпо/Loko)

**Роль**: Ти — Senior Full-Stack Developer та експерт з інтеграції API (OAuth 2.1, Telegram Bot API) та архітектури автономних агентів. Твоя мета — створити MVP (Minimum Viable Product) Telegram-бота для хакатону "Сільпо AI Factory".

**Контекст**:
Ми створюємо "Smart Watchlist" (Розумний кошик/сповіщувач) для клієнтів Сільпо/Loko. Бот підключається до профілю користувача через Сільпо MCP (OAuth 2.1), періодично перевіряє його список "Обраного" (або спеціально створений список) і надсилає персоналізовані Telegram-сповіщення на основі гнучких налаштувань.

**Технічний стек (пропонований)**:
- Backend: Node.js (TypeScript) або Python
- База даних: SQLite або PostgreSQL (зберігання токенів, налаштувань користувача, історії цін)
- Інтеграція Telegram: `node-telegram-bot-api` (або `aiogram` для Python)
- Сільпо API: Використання MCP Server endpoints (`silpo_get_my_favorites`, `silpo_find_products_batch`, `silpo_find_product_alternatives` тощо).

### 💡 Ключовий функціонал: Типи сповіщень та Налаштування

Бот повинен підтримувати наступні типи подій, а користувач має можливість через меню бота (або WebApp в Telegram) налаштовувати, які саме сповіщення він хоче отримувати.

#### 🔔 Типи сповіщень:

**💰 Ціна**
- Ціна знизилась
- Ціна змінилась
- Ціна стала вигіднішою за попередню покупку користувача
- Досягнуто встановленої користувачем бажаної ціни (Target Price)

**🔥 Акції та знижки**
- На товар з'явилась акція
- З'явилась персональна пропозиція «Власного Рахунку»
- Знижка стала більшою
- Акція скоро закінчується

**📦 Наявність**
- Товар знову з'явився в наявності
- Товар з'явився у вказаному користувачем улюбленому магазині
- Товар став доступним для доставки

**⭐ Вигідні альтернативи**
- З'явився дешевший аналог
- Є товар з більшим об'ємом за вигіднішою ціною
- З'явився аналог із кращою ціною за одиницю (кг/л)

**🛒 Вигідна покупка (Smart Buy)**
- Зараз вигідно купити товар зі списку (історичний мінімум ціни)
- Кілька товарів з обраного одночасно стали вигідними
- Система знайшла вигідну комбінацію товарів / пропозицій

#### ⚙️ Налаштування сповіщень користувачем (Приклад структури в БД):
Користувач сам обирає тригери. Модель даних користувача має підтримувати прапорці (checkboxes) для кожної категорії:
- *Ціни*: [x] Зниження ціни, [x] Досягнення моєї ціни, [ ] Будь-яка зміна ціни
- *Акції*: [x] Нові акції, [x] Персональні пропозиції, [ ] Завершення акції
- *Наявність*: [x] Знову в наявності, [x] З'явився для доставки
- *Альтернативи*: [x] Дешевший аналог, [ ] Вигідніша упаковка
- *Вигідні покупки*: [x] Вигідний момент для покупки, [x] Вигідна комбінація товарів

#### 🕒 Частота сповіщень (Anti-Spam):
Користувач повинен мати змогу обрати режим:
1. **Важливі** — тільки коли справді є суттєва зміна (велике падіння ціни, з'явився дефіцитний товар).
2. **Усі** — повідомляти про всі обрані події одразу.
3. **Щоденний підсумок** (Daily Digest) — одне повідомлення з усіма змінами за день (наприклад, о 10:00 ранку або ввечері перед закупкою).

### 📝 Завдання на цю сесію (Покроковий план):

1. **Ініціалізація проекту та Бази Даних**:
   - Створи базову структуру проекту.
   - Спроектуй схему БД: `users` (з налаштуваннями частоти та типами сповіщень), `products_state` (історія цін, наявність), `user_target_prices` (бажані ціни).

2. **Модуль Авторизації (OAuth 2.1 + PKCE)**:
   - Реалізуй флоу авторизації через Telegram.
   - Збереження `refresh_token` та логіка автоматичного отримання нового `access_token`.

3. **Telegram UI (Налаштування)**:
   - Створи меню бота (Inline Keyboards) для налаштування типів сповіщень та частоти (Важливі/Усі/Підсумок).

4. **Сільпо API Клієнт та Background Worker**:
   - Налаштуй періодичний збір даних з урахуванням Rate Limiting.
   - Аналіз зібраних даних: порівняння з `products_state` та генерація подій (Events: `PRICE_DROP`, `IN_STOCK`, `PROMO_STARTED`, `CHEAPER_ALTERNATIVE`).

5. **Модуль маршрутизації сповіщень (Notification Engine)**:
   - Фільтрація згенерованих подій на основі налаштувань конкретного користувача.
   - Агрегація повідомлень, якщо користувач вибрав "Щоденний підсумок".
   - Відправка красивих, структурованих повідомлень.
