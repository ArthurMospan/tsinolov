# Цінолов від Сільпо

Цінолов — Telegram Mini App для контролю цін на товари з «Улюблених» у Сільпо. Користувач підключає Кабінет Сільпо, обирає адресу доставки або фізичний магазин для самовивозу, задає бажані ціни й отримує сповіщення тоді, коли з’являється реальна причина купити товар вигідніше.

## Що вміє сервіс

- показує актуальні «Улюблені товари» для вибраної адреси доставки або магазину самовивозу;
- шукає товари в каталозі та додає їх до офіційних «Улюблених» Сільпо;
- встановлює індивідуальну бажану ціну;
- відстежує ціни, акції, персональні пропозиції та наявність;
- знаходить дешевший сумісний товар за брендом, типом і фасовкою;
- додає товар або добірку товарів у кошик Сільпо;
- відкриває Кабінет Сільпо, улюблені товари й кошик прямо з Mini App.

## Як усе працює

1. Telegram передає Mini App підписані дані користувача. Backend перевіряє їх перед доступом до API.
2. Користувач проходить OAuth 2.1 PKCE та підключає свій Кабінет Сільпо.
3. Backend через Silpo MCP отримує профіль, останній спосіб отримання, каталог, улюблені товари, ціни, акції та кошик. Для доставки користувачу показується його адреса, а технічний `branchId` точки комплектації залишається внутрішнім.
4. Локальна база зберігає лише налаштування, бажані ціни й попередній підтверджений стан товарів. Для production використовується Turso, локально — SQLite.
5. Перевірка запускається через 5 секунд після старту процесу, а далі — кожні 5 хвилин. Для одного користувача її також можна запустити одразу після встановлення бажаної ціни.
6. Рушій порівнює новий стан із попереднім у тому самому магазині та надсилає Telegram-сповіщення лише про нову подію.

При зміні адреси доставки або магазину самовивозу попередній стан не використовується для порівняння. Це захищає від хибних сповіщень через різні ціни й асортимент у різних точках комплектації.

## Алгоритми сповіщень

### Бажана ціна досягнута

Спрацьовує, коли актуальна ціна менша або дорівнює встановленій користувачем. Після успішного сповіщення бажана ціна скидається, тому одна й та сама подія не дублюється.

### Помітне зниження ціни

Порівнюється поточна ціна з останньою зафіксованою ціною. Сповіщення надсилається лише тоді, коли зниження одночасно становить щонайменше **5%** і **2 ₴**.

### Нова акція

Спрацьовує тільки при переході товару зі стану «без акції» у стан «є акція». Повторна перевірка тієї самої акції повідомлення не створює.

### Велика знижка

Товар вважається особливо вигідним, якщо MCP позначає його як Smart Buy або знижка від звичайної ціни становить щонайменше **20%**. Повідомлення надсилається лише на початку такого стану.

### Персональні пропозиції

Активні пропозиції з Кабінету Сільпо порівнюються за ID та змістом. Перший запит створює базовий стан без зайвого повідомлення; надалі надсилаються тільки нові або змінені активні пропозиції.

### Товар знову в наявності

Наявність береться для активного магазину й релевантного часового слота. Зміна вважається реальною тільки після **двох послідовних однакових перевірок**. Якщо MCP не може надійно підтвердити наявність, сповіщення не надсилається.

### Доставка знову доступна

Працює лише для товарів, де MCP повертає окремий статус доставки. Як і наявність, позитивна зміна підтверджується двома послідовними перевірками.

### Дешевший аналог

Пошук альтернатив запускається при зміні ціни або щонайменше раз на 6 годин. Кандидат має:

- бути доступним у тому самому магазині та способі отримання;
- відповідати категорії, бренду, типу, фасовці та ключовим характеристикам;
- не мати конфліктних властивостей;
- бути дешевшим щонайменше на **5%** і **2 ₴** — за одиницю товару або за порівнювану вагу/об’єм.

Надсилається тільки новий або вигідніший за попередній аналог. Якщо бажана ціна основного товару вже досягнута, сповіщення про аналог у цій перевірці не дублює її.

## Технології

- **Frontend:** React 19, TypeScript, Vite, Telegram Web App API;
- **Backend:** Node.js 22, TypeScript, Express, Telegraf;
- **Інтеграція:** Silpo MCP, OAuth 2.1 PKCE;
- **Дані:** Turso/libSQL у production, SQLite для локального запуску;
- **Deployment:** Render або Docker Compose з Caddy.

## Локальна перевірка

```bash
npm ci --prefix bot
npm ci --prefix webapp
npm run build --prefix webapp
```

Створіть `bot/.env`:

```env
BOT_TOKEN=telegram_bot_token
WEBAPP_URL=https://public-https-address
PORT=3000
```

Запуск backend разом зі зібраним Mini App:

```bash
npm run dev --prefix bot
```

Telegram відкриває Mini App лише за публічною HTTPS-адресою. Без `TURSO_DATABASE_URL` застосунок автоматично створить локальний `bot/database.sqlite`, який ігнорується Git.

Перевірки перед комітом:

```bash
npm test --prefix bot
npm run build --prefix bot
npm run build --prefix webapp
npm run lint --prefix webapp
```

Production-налаштування описане в [DEPLOYMENT.md](./DEPLOYMENT.md).
